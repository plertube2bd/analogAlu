# 1.12.0 검증 보고서

검증 환경: Windows 11, JDK 25.0.3, Gradle 9.8.1, Minecraft 26.3, Fabric Loader 0.19.5, Fabric API 0.165.0+26.3, Analog ALU 0.1.5 (저장소 최신 소스로 빌드. 0.1.0, 0.1.2, 0.1.3과 저장소에 올라 있는 0.1.5 jar도 확인)

## 1.12.0에서 다시 한 검사

1.12.0은 ALU 0.1.5 이상에서 레드스톤 대신 전기로 작동하게 했고, 정거장이 옆 상자나 인벤토리의 전차를 소환하고 카트 도착 대신 탑승할 때 신호를 내도록 바꿨습니다.

- `gradle clean build` 성공, `tools/validate_resources.py` 통과.
- 서버 게임 테스트 152개 전부 통과. ALU 없음, 0.1.0, 0.1.2, 0.1.3, 저장소의 0.1.5 jar, 최신 소스로 빌드한 0.1.5 모두 통과했고, 최신 0.1.5로 3회 반복해 전부 통과했습니다. 압축을 새로 푼 소스에서도 빌드와 테스트를 다시 통과했습니다.
- 정거장 테스트 15개와 전기 테스트 16개를 새로 추가했습니다. 전기 테스트는 전기가 있는 ALU에서만 실제로 돌고, 나머지 환경에서는 건너뜁니다.
- 일반 레드스톤에 기대던 기존 테스트는 어느 환경에서나 같은 뜻이 되도록 테스트 전용 신호 블록으로 바꿨습니다. 그래서 기존 기능도 전기 모드에서 함께 확인됐습니다.
- 실제 클라이언트 테스트 통과 (`gradle runClientGameTest`). ALU 0.1.5(전기)와 ALU 0.1.3(레드스톤) 양쪽에서 돌렸고, 싱글플레이와 전용 서버 접속을 모두 포함합니다.
- 빌드된 jar를 ALU 0.1.5와 함께 실제 서버에 넣어 구동 확인.
- 이전 월드 호환: 1.9.0으로 저장한 월드를 ALU 0.1.5와 1.12.0 jar로 열면 정거장, 벨트, 기계가 방향을 유지한 채 남아 있습니다.

**서버 게임 테스트로 확인한 내용**

| 분야 | 확인한 내용 |
|---|---|
| 회로 읽기 | 9V 배터리 회로의 + 쪽 케이블이 세기 10~12로 읽힘, 부하를 지난 쪽은 0, 열린 회로는 0 |
| 레일, 모터 | 동력 선로가 전기로 출발하고 전압에 맞는 속도로 달림, 모터가 전기로 가속, 레드스톤 블록으로는 둘 다 움직이지 않음 |
| 기계 | 기계가 전기로 켜짐, 레드스톤으로는 켜지지 않음, "가동" 모드 제어기도 전기가 있어야 작동 |
| 컨베이어 | 한 칸만 전기가 닿아도 줄 끝까지 아이템 운반, 회로를 끊으면 멈춤, 전기 없이는 레드스톤이 있어도 멈춰 있음 |
| 중계 | 이동수단 제어기가 전기를 동력 선로로 넘김, 축전기가 케이블로 충전됨 |

| 탑승 신호 | 타면 15, 내리면 0, 타면 동력 선로의 전차가 출발. 전기 모드에서도 마찬가지 |
| 도착 | 사람을 태우고 들어온 전차는 신호 없이 멈춤, 연결 열차 뒤 칸에 사람이 타고 있어도 신호 없음, 비교기로 카트 유무를 읽음 |

**실제 클라이언트로 확인한 내용**

- 배터리, 스위치, 부하, 케이블로 만든 회로에서 스위치를 마우스로 클릭해 닫으면 컨베이어가 아이템을 상자로 나르고 기계가 켜집니다. 다시 클릭해 열면 컨베이어가 멈춥니다. (`docs/previews/electric_circuit.png`)
- 생존 모드에서 전차 없이 우클릭하면 소환되지 않습니다.
- 인벤토리(핫바가 아닌 칸)에 전차를 넣고 우클릭하면 소환되고 인벤토리에서 빠집니다. (`docs/previews/station_summoned.png`)
- 마우스 클릭으로 전차에 타면 정거장 신호로 동력 선로가 풀려 전차가 출발합니다.

**하지 않은 검사**

- 전원은 배터리만 시험했습니다. 석탄, 풍력, 태양광 발전기로는 돌려 보지 않았습니다. 같은 전압 읽기를 쓰지만 실제로 확인하지는 않았습니다.
- 합선과 케이블 손상은 ALU 쪽 동작이라 시험하지 않았습니다.
- 저장소의 0.1.5 jar는 서버 게임 테스트까지만 돌렸습니다. 실제 클라이언트는 최신 소스로 빌드한 jar와 0.1.3으로 돌렸습니다.
- 비교기는 정거장의 출력값만 확인했습니다. 실제 비교기 블록을 붙여 회로를 돌려 보지는 않았습니다.
- ALU 회로로 자동 출발시키는 것은 시험하지 않았습니다. 테스트 전용 신호 블록으로만 확인했습니다.
- 멀티플레이에서 여러 플레이어가 동시에 쓰는 경우는 시험하지 않았습니다.

## 1.11.0에서 한 검사

1.11.0은 컨베이어가 레일처럼 곡선, 경사, 양쪽 합류로 이어지게 했습니다.

- `gradle clean build` 성공, `tools/validate_resources.py` 통과.
- 서버 게임 테스트 121개 전부 통과. ALU 0.1.3, 0.1.2, 0.1.0, ALU 없음 네 경우 모두 통과했고, ALU 0.1.3으로 3회 반복해 전부 통과했습니다. 압축을 새로 푼 소스에서도 빌드와 테스트를 다시 통과했습니다.
- 실제 클라이언트 테스트 통과 (`gradle runClientGameTest`). 싱글플레이와 전용 서버 접속을 모두 포함합니다.
- 빌드된 jar를 ALU 0.1.3과 함께 실제 서버에 넣어 구동 확인.
- 이전 월드 호환: 1.9.0으로 저장한 월드를 1.11.0 jar로 열면 벨트의 방향이 유지됩니다. 전에 꺾어 둔 칸은 곧은 모양으로 남아 있고, 주변 벨트를 다시 놓으면 곡선이 됩니다.

**서버 게임 테스트로 확인한 내용**

| 분야 | 확인한 내용 |
|---|---|
| 곡선 | 좌우 양방향 곡선을 지나 상자까지 도착, 옆줄을 치우면 직선으로 돌아감 |
| 줄 끝 꺾기 | 끝 칸에서 방향을 틀어 놓으면 끝 칸이 꺾임, 평행하게 놓으면 꺾이지 않음, 상자로 이어진 끝 칸은 꺾이지 않음 |
| 합류 | 양쪽에서 들어오면 T자가 되고 양쪽 아이템이 모두 도착, 한쪽을 치우면 곡선, 다 치우면 직선, 뒤에서도 들어오면 직선 유지, 곧은 줄에 옆줄 합류 |
| 경사 | 2단 오르막과 2단 내리막으로 상자까지 도착, 돼지가 오르막을 탐, 멈춘 경사가 아이템을 붙잡음, 겹쳐 놓은 벨트는 평평하게 유지 |
| 회전 | 벨트 상태가 회전과 대칭을 따름 |

**실제 클라이언트로 확인한 내용**

- 마우스 클릭으로 벨트를 놓아 모서리를 돌면 끝 칸이 꺾이고, 아이템이 그 모서리를 돌아 상자에 들어갑니다.
- 곡선의 화살표가 휘어져 이어지고, 멈춘 벨트는 어둡게 표시됩니다. (`docs/previews/conveyor_shapes.png`)
- 경사가 평지 벨트와 틈 없이 이어집니다. (`docs/previews/conveyor_slope.png`)
- 양쪽에서 들어오는 T자가 끊기지 않고 이어집니다. (`docs/previews/conveyor_both.png`)

**하지 않은 검사**

- 플레이어가 벨트를 타는 것은 시험하지 않았습니다. 동물과 아이템으로만 확인했습니다.
- 배나 비행선에 실린 벨트를 실제로 회전시켜 내려 보지는 않았습니다. 블록 상태의 회전만 확인했습니다.
- 경사와 곡선을 벨트 위를 달리는 많은 아이템으로 부하 시험하지는 않았습니다.

## 1.10.0에서 한 검사

1.10.0은 카트 적재기와 하역기를 없애고, 자동화 기계 조합법에 반도체를 넣고, 화물 전차를 32칸으로 줄이고, 선로 부설기에 대각선 방식을 넣고 꺾임 연결을 고쳤습니다.

- `gradle clean build` 성공, `tools/validate_resources.py` 통과. 이 검사는 이제 자동화 기계 7종의 반도체 조합법, 4개 제작, ALU 없을 때의 조합법을 확인합니다.
- 서버 게임 테스트 106개 전부 통과. ALU 0.1.3으로 통과했습니다. 104개이던 시점에 ALU 0.1.3, 0.1.2, 0.1.0, ALU 없음 네 경우 모두 통과했고, ALU 0.1.3으로 3회 반복해 전부 통과했습니다. 그 뒤 추가한 2개는 테스트 코드만 늘렸고 모드 코드는 바뀌지 않았습니다. 압축을 새로 푼 소스에서도 빌드와 테스트를 다시 통과했습니다.
- 실제 클라이언트 테스트 통과 (`gradle runClientGameTest`). 싱글플레이와 전용 서버 접속을 모두 포함합니다.
- 빌드된 jar를 ALU 0.1.3과 함께 실제 서버에 넣어 구동 확인.

**이전 월드 호환 (1.9.0으로 저장한 월드를 1.10.0 jar로 열어 확인)**

| 저장해 둔 것 | 1.10.0에서 본 결과 |
|---|---|
| 설치된 적재기, 하역기 | 블록과 내용물이 사라짐. 충돌 없음. 블록마다 로그에 오류 한 줄이 남음 |
| 벌목기 | 방향과 내용물 유지 |
| 적재기 아이템이 든 상자 | 그 아이템만 사라지고 나머지 유지 |
| 적재기가 설치된 배 | 그 칸만 비고 구조물과 나머지 칸 유지 |
| 36번째 칸에 물건이 든 화물 전차 | 물건이 앞쪽 빈칸으로 옮겨짐 |

**서버 게임 테스트로 확인한 내용**

| 분야 | 확인한 내용 |
|---|---|
| 화물 싣고 내리기 | 동력 선로 위의 호퍼가 전차를 채우고, 아래의 호퍼가 비움 |
| 조합법 | ALU가 있으면 반도체로 벌목기 4개, 레드스톤으로는 만들 수 없음. ALU가 없으면 레드스톤으로 1개. 기계 7종의 조합법이 모두 존재함 |
| 화물칸 | 32칸, Shift+클릭 양방향, 옛 칸의 물건은 빈칸으로 이동, 빈칸이 없으면 전차 옆에 떨어짐 |

**실제 클라이언트로 확인한 내용**

- 마우스 클릭으로 대각선을 깔고, 허공을 클릭해 ㄱ자로 바꾼 뒤 이어서 꺾습니다. 두 구간은 끊기지 않고 연결됩니다. (`docs/previews/track_layer_diagonal.png`)
- 전차가 대각선을 달릴 때 차체는 대각선 방향에서 5도 안으로 유지됩니다. 측정값은 -45.0~-46.4도입니다. (`docs/previews/tram_on_diagonal.png`)
- 클릭으로 화물칸을 열면 8칸 4줄로 표시되고, 첫 칸과 마지막 칸의 물건이 보입니다. (`docs/previews/cargo_tram_menu.png`)
- 조합법 책에서 찾은 채굴 드릴에 반도체 2개가 재료로 나오고 결과가 4개입니다. (`docs/previews/recipe_book_machine.png`)
- 적재기와 하역기를 뺀 기계 6종과 제어기의 모델이 정상입니다. (`docs/previews/machines.png`)

**하지 않은 검사**

- 없앤 기계의 아이템이 플레이어 인벤토리에 있는 월드는 열어 보지 않았습니다. 상자에 든 경우만 확인했습니다.
- 생존 모드에서 전동 레일이 일반 레일로 바뀔 때의 비용과 드롭은 시험하지 않았습니다. 꺾임 자체는 크리에이티브로 확인했습니다.
- 높이 차이가 있는 대각선은 일반 카트로만 달려 봤습니다. 전차, 연결 열차, 모터 IV 속도는 평지 대각선에서만 확인했습니다.
- 실제 클라이언트 테스트는 ALU 0.1.3으로만 돌렸습니다. ALU 없음, 0.1.0, 0.1.2는 서버 게임 테스트로 확인했습니다.

- 빌드된 jar를 ALU 0.1.2와 함께 실제 서버에 넣어 구동 확인.
- 이전 월드 호환: 1.8.0으로 구조물을 저장한 월드를 1.9.0으로 열어도 구조물이 유지됩니다.

**이전 월드 호환**: 1.6.1 서버에서 설계도와 통나무가 든 상자, 기계가 있는 월드를 만들어 1.6.2로 열었습니다. 크래시 없이 설계도만 사라지고 통나무와 기계는 남습니다.

**정적 검사**: `tools/validate_resources.py` 통과. 드롭 테이블, 곡괭이 태그, 언어 파일 쌍까지 검사합니다.

## 테스트가 잡아낸 문제 (수정 완료)

- 화물 전차를 54칸으로 만들면 주행 중 게임이 멈췄습니다. 바닐라 카트 인벤토리가 36칸 고정이라 36칸으로 맞췄습니다.
- 벌목기가 묘목까지 상자로 보내 공장이 멈췄습니다. 옆 기계를 먼저 채우도록 고쳤습니다.
- 연결된 열차가 서로 반대로 출발하거나 고속에서 충돌로 약 20 m/s에 묶였습니다. 맨 앞 카트를 뒤 카트가 따라가는 방식으로 고쳤습니다.
- 벌목 도중 재시작하면 잎이 사라진 줄기가 나무로 인식되지 않아 자리가 막혔습니다. 벌목 대상을 저장하도록 고쳤습니다.
- 나란히 놓인 기계의 작업 범위가 어긋나 나무 공장이 멈출 수 있었습니다. 테스트 위치에 따라서만 드러나던 문제로, 제어기에 연결된 기계가 구역을 공유하도록 고쳤습니다.

## 하지 않은 검사

- 사람이 직접 플레이한 검증은 없습니다. 조작감, 멀티플레이 서버에 여러 플레이어가 접속한 상황, 장시간 가동 성능은 확인하지 않았습니다.
- 농작물 공장과 채굴 공장은 각 기계 동작을 따로 확인했고, 나무 공장처럼 전체 사이클을 돌려 보지는 않았습니다.
- ALU Upward Hopper와 화물 전차의 직접 연동은 시험하지 않았습니다.

## 참고: Analog ALU 쪽 경고

클라이언트 로그에 `Missing model for variant: analog_alu:upward_hopper[facing=north/south/west/east]` 경고가 나옵니다. 0.1.2에서도 ALU jar의 `upward_hopper` 블록 상태에 `facing=down`만 정의되어 있어 나오는 경고이고, 이 모드와는 무관합니다. 수평 방향 Upward Hopper가 깨진 모델로 보일 수 있습니다.
